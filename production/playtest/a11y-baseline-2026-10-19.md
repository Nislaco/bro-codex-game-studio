## Keyboard-Only Playthrough

**Verified in the live running game via MCP `simulate_key` (real key events):**

| Step | Action | Expected | Result |
|------|--------|----------|--------|
| 1 | `grab_focus()` on cell (2,4) | focus owner = `Cell_2_4` | PASS (`owner=Cell_2_4`) |
| 2 | `simulate_key ENTER` | disc placed, turn advanced | PASS (`board[2][4]=1`, `currentPlayer` advanced) |
| 3 | `simulate_key RIGHT` | focus moves to (2,5) | PASS (`focus now: Cell_2_5`) |
| 4 | Tab order | 13 focusable UI elements registered | PASS (`count: 13`) |

**Harness coverage (S14-AT-3..6), so this is CI-verified, not MCP-only:**
- S14-AT-3: every cell is `FOCUS_ALL`; `focus_neighbor_left/right` wired to `../Cell_r_c`
- S14-AT-4: Enter on a focused cell places a disc
- S14-AT-5: mouse click places a disc (regression guard for the `gui_input` bind-order contract)
- S14-AT-6: a non-activation key (Tab) does not place a disc

### Focus Order
- Arrow keys move between adjacent cells (LTR/TTB) via `focus_neighbor_*`.
- Edge cells have empty neighbor paths (no wrap-around).
- Tab order: Mode → Difficulty → Language → Volume → board cells → Restart.

## Colorblind Simulation (Protanopia/Deuteranopia)

| Element | Distinguishable? | Rationale |
|---------|------------------|-----------|
| Legal-move hint vs base cell | **YES** | Gold vs green differs in **hue AND lightness** (3.78:1), not hue alone — survives protanopia/deuteranopia |

| Black disc vs cell base | YES | 3.44:1 lightness difference |
| White disc vs cell base | YES | 6.10:1 lightness difference |

**Design note:** the original light-green hint (1.52:1 vs base) was indistinguishable for both colorblind users *and* normal vision. The gold hint fixes both.

## Defects Found & Fixed During This Pass

| ID | Defect | Fix |
|----|--------|-----|
| A11y-D1 | Black disc vs cell base was 2.96:1 (below WCAG 3:1) | Lightened `CELL_COLOR` to `Color(0.16, 0.44, 0.16)` |
| A11y-D2 | Legal-move hint vs cell base was 1.52:1 (nearly invisible) | Changed hint to gold `Color(0.95, 0.78, 0.25)` (3.78:1) |
| A11y-D3 | Cells were not keyboard-focusable; no arrow navigation | `focus_mode = FOCUS_ALL` + `focus_neighbor_*` wiring |
| A11y-D4 | `focus_neighbor_*` paths were unresolvable (`board_grid/Cell_r_c`) | Godot resolves these **relative to the focused node**; corrected to `../Cell_r_c` |
| A11y-D5 | Enter/Space did not activate a focused cell | Replaced `is_action_pressed("ui_accept")` with explicit keycode check |
| A11y-D6 | **Clicking was broken** — `gui_input` bound with `.bind(r, c)` calls the handler as `(event, r, c)`, but the signature had the event last | Corrected signature to `_on_cell_input(event, r, c)`; added S14-AT-5 regression guard |
| A11y-D7 | `res://translations/strings.csv` did not exist (CSV was outside the Godot project root) — masked by the fallback | Moved to `src/translations/strings.csv` |
| A11y-D8 | 6 GDScript warnings (enum casts, shadowed vars, float narrowing, integer division, unused vars) | All fixed; runtime error list now empty |
